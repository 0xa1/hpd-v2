# Domain docs

## Before exploring

This repo has one context. Read `GLOSSARY.md` at the root and any relevant decisions in `docs/adr/`. If either is absent, proceed silently and let `/domain-modeling` create docs when a term or decision is settled.

## Use the glossary’s vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests. If a term is missing, verify that the project uses it before noting the gap for `/domain-modeling`.

## Flag ADR conflicts

If a proposal conflicts with an ADR, name the ADR and explain why it may be worth reopening.
